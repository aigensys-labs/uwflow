# UWflow operational state

All repository-local data created or managed while running UWflow belongs under this directory. The repository root is reserved for stable source code, configuration, documentation and tooling; Studio, Core runs, DEV workflows, tests and production lifecycle operations must not create operational folders beside those files.

| Area | Purpose | Lifecycle |
|---|---|---|
| `venv/` | Local Python virtual environment used by Core and platform operator scripts | Created on first run; ignored by Git and excluded from packages and Docker build contexts. |
| `cache/` | Local lint and tool caches | Generated on demand; disposable and never source-controlled. |
| `*.egg-info/` | Setuptools package metadata | If a packaging command creates persistent metadata, its configured location is directly under `var/`; ignored by Git and absent from clean UWflow ZIP releases. Standard Python source distributions may include their generated metadata index. Editable installs do not require a generated build directory. |
| `build/` and `dist/` | Python package build intermediates and distribution output | Generated by packaging commands; removed from source packages and never committed as runtime state. |
| `workspaces/` | Mutable analyst strategy workspaces | Created and edited by Policy Studio; source for immutable candidates. |
| `artifacts/` | DEV candidates, replay flows, History bundles, baselines and registered evaluations | Generated by Lifecycle, History and Evaluation. Immutable objects are never overwritten. |
| `releases/approved/` | Approved production deployment packages | Created after evaluation and explicit approval; retained in Git through protected review. |
| `deployments/` | Deployment provenance, current release pointer and deployment history | Written after successful production deployment. |
| `reports/` | Core applicant reports and local DEV/replay comparisons | Generated by Core and operator tools. |
| `data/history/` | Local historical datasets and database-backed data files | Owned by History; may contain large or sensitive data. |
| `operator-state/` | Local workflow selections and recovery markers | Generated by operator scripts; never source-controlled. |

Kestra Namespace Files use their own remote namespace paths such as `runtime/releases/<version>/`. Those paths are not repository directories and remain unchanged.

See [the UWflow lifecycle and storage model](../docs/architecture/lifecycle-and-storage.md) for object ownership, immutability, provenance and promotion rules.
